# Deploying Forge OS

Forge OS has three parts. The app works offline on its own; each extra part switches on more.

| Part | Where | What it adds |
|---|---|---|
| The app (PWA) | Vercel | Everything personal: plan, logging, analytics, rule-based coach, backups. Health data stays on the device. |
| Supabase | supabase.com | Community accounts, feed, follows, the notification centre. Never holds health data. |
| Coach server (`server/`) | Render | AI coach, push notifications, Strava import. Holds every secret. |

The server starts with none of its optional settings and logs what is on and off. `GET /api/health`
answers the same: `{ ok, model, keyPresent, authRequired, push, strava }`.

---

## 1. Supabase

1. Create a project.
2. In the SQL editor, run these files **in this order**. Each one is additive and safe to run again:

   | Order | File | Adds |
   |---|---|---|
   | 1 | `supabase/schema.sql` | profiles, posts, kudos, comments, follows, blocks, reports, RLS |
   | 2 | `supabase/storage.sql` | the private `post-photos` bucket and its policies |
   | 3 | `supabase/photos.sql` | thumbnail and full-size photo variants |
   | 4 | `supabase/social.sql` | follower counts and lists (accepted follows only) |
   | 5 | `supabase/unblock.sql` | the list of people you blocked, to unblock them |
   | 6 | `supabase/push.sql` | `push_subscriptions` (owner-only) |
   | 7 | `supabase/notifications.sql` | `notifications`, with an insert check that the event really happened |
   | 8 | `supabase/strava.sql` | `strava_connections` (no app access at all; the server only) |

   If you apply them through a tool that stops to confirm destructive statements (the Supabase MCP
   connector does), the `drop policy if exists` and `drop trigger if exists` lines are no-ops on a new
   project and can be left out. Keep them when re-running on a project that already has the schema.
   Afterwards, Advisors → Security should list only "SECURITY DEFINER function executable by signed-in
   users" for the helper functions: that is intended, the policies and the app call them, and each
   answers only about the caller.
3. Authentication → URL configuration: Site URL `https://forge-os-black.vercel.app`; redirect URLs
   `https://forge-os-black.vercel.app/auth/callback` and `https://forge-os-black.vercel.app/auth/reset`.
4. Project settings → API: copy the **Project URL**, the **anon** key (public by design) and the
   **service_role** key (secret: it bypasses row-level security, so it goes on Render only, never in
   Vercel or the app).

Housekeeping: the inbox shows 90 days. Once a quarter, run
`delete from public.notifications where created_at < now() - interval '90 days';`

## 2. Coach server on Render

`render.yaml` is a Blueprint: Render → New → **Blueprint** → this repo. It deploys `main`, runs
`npm ci --omit=dev && npm ci --omit=dev --prefix server` (the second installs `web-push`, a server-only
dependency), starts `npm run server` and checks `/api/health`. It never builds the frontend: `vite build`
needs more memory than the free plan gives.

### Environment variables

| Variable | Needed for | Value |
|---|---|---|
| `ALLOWED_ORIGINS` | all | `https://forge-os-black.vercel.app` (comma-separate several) |
| `ANTHROPIC_API_KEY` | AI coach | your key |
| `COACH_ACCESS_TOKEN` | AI coach | generated by the Blueprint; paste it into Profile → AI coach |
| `COACH_MODEL`, `COACH_EFFORT` | AI coach | optional; defaults `claude-opus-5-5`, `medium` |
| `SUPABASE_URL` | push, Strava | the Project URL |
| `SUPABASE_ANON_KEY` | push, Strava | the anon key (used to check who is signed in) |
| `SUPABASE_SERVICE_ROLE_KEY` | push, Strava | the service_role key |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | push | see below |
| `VAPID_EMAIL` | push | a contact address for push services, e.g. `mailto:vishal@forge-os.app` |
| `STRAVA_CLIENT_ID`, `STRAVA_CLIENT_SECRET` | Strava | from your Strava API application |
| `APP_URL` | Strava | `https://forge-os-black.vercel.app`; Strava sends members back to `APP_URL/settings/strava/callback`. Defaults to the first `ALLOWED_ORIGINS` entry |

Variables marked `sync: false` in `render.yaml` are typed into the Render dashboard and never committed.

### VAPID keys (push notifications)

Generate once, and keep them: changing them invalidates every existing subscription.

```bash
cd server && npm ci && npx web-push generate-vapid-keys
```

Put both keys on Render. The app fetches the public key from `GET /api/push/config`, so Vercel needs
nothing. (`VITE_VAPID_PUBLIC_KEY` on Vercel is optional and only skips that request.)

### The free plan sleeps

Render's free instances sleep after about 15 minutes without traffic and can take up to a minute to wake.

- **AI coach and Strava sync:** the first request after a sleep is slow. The coach falls back to the
  rule-based answer if it times out.
- **Social pushes** (kudos, comments, follows) are sent while handling the request that caused them,
  so they arrive, just late after a sleep.
- **Scheduled reminder pushes are not reliable on the free plan.** They are held in the server's
  memory: a sleeping instance doesn't fire them, and a restart or redeploy forgets them until each
  member next opens the app. The in-app reminders (shown while the app is open) are unaffected.
  For dependable reminder pushes, move the service to a paid instance that doesn't sleep.

## 3. Strava

1. Create an application at <https://www.strava.com/settings/api>.
   - **Authorization Callback Domain:** `forge-os-black.vercel.app` (the domain only, no `https://`).
   - Copy the **Client ID** and **Client Secret** to Render as `STRAVA_CLIENT_ID` and `STRAVA_CLIENT_SECRET`.
2. Redeploy. The server log says `Strava import: on (redirect https://forge-os-black.vercel.app/settings/strava/callback)`.

**Single Player Mode.** A new Strava application can connect only one athlete, its owner, until Strava
reviews it. Before inviting the community (200 to 300 members), apply through Strava's developer
program to raise the athlete limit. Until then everyone else sees an error from Strava when connecting.

**Rate limits** apply to the whole application, not per member (see your application's page for the
current numbers). The server spaces out syncs (one every 2 minutes per member, up to 200 activities a
sync) and passes Strava's 429 on as "Strava is busy. Try again in N minutes". Sync is manual for now.
A future auto-sync should run only when the last sync is over 6 hours old, with 0 to 5 minutes of
random delay, so 200 members opening the app at 7 am don't all hit Strava at once.

What crosses the wire: the server asks for `activity:read` only and returns id, name, type, workout type,
distance, times, speeds, average heart rate, start dates and elevation gain. Maps, polylines,
coordinates and splits are dropped on the server. The tokens never leave the server; imported
activities are stored on the member's device only.

## 4. The app on Vercel

Framework preset **Vite**, build `npm run build`, output `dist`. Environment (baked in at build time,
so redeploy after changing):

| Variable | Value |
|---|---|
| `VITE_SUPABASE_URL` | the Project URL |
| `VITE_SUPABASE_ANON_KEY` | the anon key |
| `VITE_COACH_URL` | `https://<your-service>.onrender.com` (can also be set in Profile) |
| `VITE_VAPID_PUBLIC_KEY` | optional, see above |

No Strava variable is needed in Vercel: the client id and secret stay on the server.

`vercel.json` rewrites deep links (including `/settings/strava/callback` and `/notifications`) to
`index.html`, never caches `sw.js` and sets `X-Content-Type-Options`, `Referrer-Policy`,
`X-Frame-Options` and `Permissions-Policy`. There is no Content-Security-Policy yet: the coach server
URL can be changed in Profile at run time, so a fixed `connect-src` list would break that. Adding one
means deciding on a fixed server URL first.

---

## 5. Check it

1. `https://<your-service>.onrender.com/api/health` shows `"push": true` and `"strava": true`.
2. `https://forge-os-black.vercel.app/sw.js` returns JavaScript, not HTML.
3. On a phone (on iPhone, add Forge OS to the home screen first): sign in to the community, Profile →
   **Enable notifications**. From a second account, give one of your posts kudos: a push arrives and the
   bell shows 1.
4. Profile → **Connect Strava** → approve → **Sync now**: the toast says what was imported, and the runs
   appear under Training → Runs.

## Local checks

```bash
npx tsc --noEmit && npx vitest run && npm run build
bash supabase/tests/run.sh                                  # RLS, needs Postgres server binaries
POSTGREST=/path/to/postgrest bash supabase/tests/api.sh     # needs PostgREST v12
```

CI runs the same on every push to `main` (`.github/workflows/ci.yml`).
